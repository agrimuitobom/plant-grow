# 運用ハンドブック (Runbook)

このドキュメントは **エンジニアでない先生** が「植物生育管理」アプリを運用・引き継ぎするためのものです。
コードの説明は README.md にあります。ここには「困った時にどうするか」だけを書きます。

---

## 1. このアプリの全体像

| 部品 | 役割 | 管理画面 |
|------|------|---------|
| Firebase Hosting | アプリ本体の配信 (https://plant-research-b106b.web.app) | [Firebase Console](https://console.firebase.google.com/project/plant-research-b106b) |
| Firebase Authentication | ログイン (ID + パスワード) | Console → Authentication |
| Firestore | 観察記録・名簿・コメントの保存 | Console → Firestore Database |
| Cloud Storage | 写真の保存 | Console → Storage |
| Cloud Functions | パスワードリセットなどの特権処理・夜間バックアップ | Console → Functions |
| GitHub | ソースコード置き場。main に変更が入ると自動で本番反映 | https://github.com/agrimuitobom/plant-grow |
| Sentry | エラーの自動収集 (設定している場合) | https://sentry.io |

**大事な原則**: コードを変えなくても、日常運用は全部アプリ内 (教員モード) と Firebase Console で完結します。

## 2. 日常運用 (よくある対応)

### 生徒がパスワードを忘れた
1. 教員アカウントでログイン → 「クラスを見る」
2. その生徒を選ぶ → 「🔑 パスワードをリセット」
3. 表示された仮パスワードを紙にメモして生徒に渡す
4. ※ この操作は「操作ログ」に自動記録されます

### 生徒が「オフラインで開けない」と言ってきた
- 一度 **オンライン状態で** アプリを開かせて、画面下に「✓ オフライン対応の準備ができました」が出るまで待つ
- その後はオフラインでも開けます。**初回だけは必ずオンラインが必要** です

### 新しい先生を教員にしたい
1. その先生にアプリの「初回登録」でアカウントを作ってもらう
2. 一度観察記録を保存してもらう (名簿に載せるため)
3. 既存の教員が「教員管理」タブ → 「教員にする」

### 保護者に子どもの記録を見せたい
1. 教員モード → 生徒を選ぶ → 「🔗 保護者リンクを発行」
2. 表示された URL を保護者に伝える (72 時間で自動失効・いつでも取消可)

### 記録を間違えて上書きしてしまった
- 観察フォームの「編集履歴」を開くと過去の状態が残っています
- 「この内容を復元」→「保存する」で戻せます

## 3. 年次運用 (年度の変わり目)

### 手順 1: 旧年度をアーカイブする (年度末)
1. 教員モード → 「教員管理」タブ → 「年度アーカイブ」カード
2. 「📦 この年度をアーカイブする」→ 確認して実行
3. これでクラス全体が **読み取り専用** になります
   - 生徒・教員とも新しい記録・コメント・イベントを追加できなくなる (サーバ側で拒否)
   - 閲覧・印刷・CSV エクスポートは今まで通り可能
   - 間違えた場合は同じ場所からいつでも解除可能
4. 操作は「操作ログ」に自動記録されます

### 手順 2: 新年度のクラスを始める (4 月)
1. 新しいクラス ID を決める (例: `2027-grade3a`。半角英数とハイフンのみ)
2. 生徒への案内: 「ログイン画面の下の『クラス: … [変更]』から新しいクラス ID を入れてから初回登録」
3. 先生自身も新クラスで初回登録 → 初期セットアップバナーから「最初の教員として登録」
4. 旧クラスのデータはそのまま残ります (教員はヘッダーのクラス切替で行き来できます)

### 過去年度を見たいとき
- 教員: ヘッダーの「クラス: …」ドロップダウンで旧年度に切替 (複数クラスの教員に自動で表示)
- 生徒: ログイン画面のクラス変更で旧年度のクラス ID + 当時の ID・パスワードでログイン (読み取り専用)

### プライバシーポリシーの更新
- `src/components/PrivacyPolicy.tsx` の「最終更新日」等を編集して GitHub で main にマージすると反映されます

## 4. トラブル対応

### 請求額が急に増えた
1. [Cloud Console → 請求](https://console.cloud.google.com/billing) で内訳を確認
2. 教員ダッシュボードの「📷 写真容量」で写真の使用量を確認
3. 原因が分からなければ、いったん Firebase Console → Hosting でサイトを無効化して調査

### エラーが頻発している気がする
- Sentry (設定済みの場合) にエラーが集約されています
- Cloud Functions のエラーは Console → Functions → ログ で確認

### データを誤って消した / 壊した
毎日 JST 03:00 に自動バックアップが取られています (30 日分保持)。
復元は **エンジニアの補助を推奨** しますが、コマンドは README の「バックアップ / 復元」にあります。
⚠️ 復元は上書き操作です。必ず先に手動バックアップを取ってから。

### アプリが真っ白になる / 開けない
1. まず端末側: ブラウザを完全終了して開き直し (iPad はマルチタスクから上スワイプ)
2. 全員で起きているなら: GitHub の Actions タブで最新のデプロイが失敗していないか確認
3. 直近のマージが原因なら: GitHub でそのマージを Revert → 自動で前の状態に戻る

## 5. 引き継ぎチェックリスト (担当者交代時)

新しい担当者に渡すアカウント・権限:

- [ ] **GitHub リポジトリ** の管理者権限 (Settings → Collaborators)
- [ ] **Firebase / Google Cloud プロジェクト** のオーナー権限 (IAM で追加)
- [ ] **Sentry** プロジェクトへの招待 (使っている場合)
- [ ] アプリ内の **教員ロール** (教員管理タブから追加)
- [ ] このドキュメントと README の場所

引き継いだ人が最初にやること:

- [ ] 教員モードでログインして生徒一覧が見えるか確認
- [ ] Cloud Console の予算アラートの通知先を自分のメールに変更
- [ ] GitHub の Dependabot PR (依存更新) が来たら CI が緑なのを確認してマージする習慣をつける
